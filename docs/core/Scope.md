# 视觉检测系统范围

## 1. 文档目的

本文定义视觉检测系统 v1 的目标、用户可见能力和版本边界。

跨组件行为、状态转换、并发裁决和资源生命周期见 [Contract.md](./Contract.md)。宏观组件划分与依赖关系见 [Architecture.md](./Architecture.md)。

## 2. 场景与目标

系统面向单摄像头、手动触发的工件视觉检查场景。

v1 目标：

- 摄像头采集不受 GUI 和检查逻辑影响；
- GUI 持续预览摄像头的最新帧；
- 检查使用提交检查申请时的最新完整帧；
- 检查方案通过配置文件定义和选择；
- GUI 支持编辑、校验、测试和保存检查方案；
- 检查核心使用明确的输入和输出，不执行外部业务副作用；
- 同一时间最多执行一次检查。

## 3. 功能范围

### 3.1 应用模式

应用包含三个互斥模式：

- 主页；
- 编辑模式；
- 生产模式。

主页用于选择配置文件，并进入编辑模式或生产模式。主页不加载检查方案。

返回主页时释放当前模式持有的配置、检查方案和展示结果。正在执行的检查在后台取消。

### 3.2 摄像头采集

- v1 只支持一个摄像头；
- 应用启动时初始化摄像头并开始采集；
- 摄像头跨所有应用模式持续运行；
- 应用退出时停止采集并关闭摄像头；
- 每次采集后，将 SDK 图像数据复制到应用拥有的内存；
- 系统提供唯一的最新帧入口；
- 新帧可以替换最新帧，但不得改变消费者已持有的旧帧。

### 3.3 GUI 预览

- GUI 使用 iced 实现；
- GUI 按自身刷新节奏读取最新帧；
- GUI 允许跳过中间帧；
- GUI 不积压待显示帧；
- GUI 不直接访问摄像头；
- GUI 通过 App Controller 发出应用命令。

### 3.4 检查方案

- 一份配置文件定义一份检查方案；
- 检查方案不关联工件种类；
- 系统不识别当前工件种类；
- 配置使用程序已注册的检查算子；
- 配置定义算子顺序、启用状态、参数和判定规则；
- v1 检查流程为线性流程；
- 配置不得包含可执行代码或任意函数地址；
- 检查算子不得执行外部业务副作用。

`DecisionRule.Expression` 在 v1 中采用封闭的结构化 AST。其范围包括：

- `Bool`、`Int64`、`Float64` 和 `String` 字面量；
- 对启用阶段显式公开的顶层判定字段的引用；
- `Not`、`And` 和 `Or` 逻辑操作；
- 同类型值的 `Eq` 和 `Ne` 比较；
- 同类型 `Int64` 或 `Float64` 值的 `Lt`、`Le`、`Gt` 和 `Ge` 比较。

Expression 只产生布尔判定，不直接读取 Frame、InspectionMetadata、派生产物或其他运行期全局状态。

### 3.5 编辑模式

进入编辑模式时，读取主页选中的配置文件，并在内存中创建可编辑草稿。

编辑模式支持：

- 修改和校验配置草稿；
- 编译临时检查方案；
- 使用最新帧执行测试检查；
- 将有效草稿写回原配置文件。

每次测试检查基于当前草稿，不要求先保存。临时方案只属于本次测试检查，不成为编辑模式的持久状态。

编辑模式不执行生产检查，测试结果必须标记为测试结果。

GUI 通过 `AppViewSnapshot.screen` 中的编辑屏幕投影取得完整 Draft Config 只读快照，包括编辑会话 `draft_version`、方案标识、修订号、名称、阶段列表、阶段参数和判定规则。GUI 不直接读取或持有可变 Draft Config。`scheme_id` 和 `revision` 不允许通过普通草稿修改命令改变。

v1 的 GUI 同一时间最多允许一个 `ModifyDraft` 命令在途。命令必须携带当前快照的 `draft_version`；提交后 GUI 必须禁止下一次草稿编辑。修改成功时，只有在收到可靠的 `DraftModified(draft_version)` 响应并观察到相同或更高版本的新编辑屏幕快照后，才能允许下一次编辑。修改失败时，GUI 在收到失败响应后基于未改变的当前快照恢复编辑。

### 3.6 生产模式

进入生产模式时，读取、校验并编译主页选中的配置文件。生产模式始终持有有效的不可变检查方案；方案可以不包含阶段。

生产模式运行期间不自动重新读取配置。生产检查由用户手动触发。

提交检查申请时固定最新完整帧、当前检查方案、模式会话和检查类型；Inspection Actor 接受申请时补充任务标识与业务开始时间并构造检查元数据。后续帧或文件变化不得影响正在执行的检查。

### 3.7 检查结果

- 检查结果关联检查编号、检查类型、帧编号、方案编号和方案修订号；
- GUI 只保留最近一次检查展示对象；
- 展示对象持有关联检查帧；
- 成功结果展示判定、文字信息及可用的可视化标记；
- 失败结果展示错误及关联检查帧。

### 3.8 超时与取消

- 检查超时、取消宽限期、Camera 停止截止、Inspection Worker 关闭截止和 Actor 关闭截止使用应用级固定值；
- 配置读取、解析、校验、方案构建和保存不设置截止时间，可以无限等待，但不得阻塞 GUI、Actor 或异步运行时执行线程；
- 检查超时、返回主页和应用优雅关机均可触发协作式取消；
- 返回主页不等待取消结束；
- 应用优雅关机先停止摄像头采集，再取消并等待当前检查结束；
- 关机开始后拒绝后续应用命令；
- 取消期间不接受新检查；
- Actor 在匹配 WorkerOutcome 之前先处理适用的取消截止消息时，应用直接 `panic`；
- 关机协调方在组件关闭确认之前先处理对应 Camera、Worker 或 Actor 关闭截止时，应用直接 `panic`。

## 4. 质量约束

- App Controller 是应用模式状态的唯一所有者；
- 模式相关命令串行处理；
- 异步模式事件隔离不同模式会话；
- 摄像头只能由 Camera Actor 访问；
- 摄像头采集不等待帧消费者；
- 已发布帧和已构建检查方案保持不可变；
- GUI 线程不执行检查核心；
- 检查在独立执行环境中运行；
- 同一时间最多执行一个检查；
- 状态和副作用由边界组件管理；
- 图像处理使用显式输入和输出。

## 5. v1 错误范围

v1 处理以下应用命令业务错误：

- `Busy`；
- `NoFrame`；
- `InvalidMode`；
- `DraftVersionConflict`；
- `ConfigLoadFailed`；
- `ConfigInvalid`；
- `ConfigSaveFailed`；
- `ShuttingDown`。

检查被接受后的正常完成、执行失败和执行超时通过异步检查事件表达。`InspectionFailed` 和 `InspectionTimedOut` 是检查终止事实，不是应用命令业务错误；业务判定 `Fail` 是正常完成结果，不是执行错误。

v1 不实现组件初始化、摄像头采集、有效配置的方案构建及组件关闭的错误恢复。完整校验成功的配置无法构建为完整 Inspection Plan 时表示内部契约被破坏；以上操作失败时直接 `panic`。

## 6. v1 范围外

v1 不包含：

- 多摄像头支持；
- 工件识别；
- 工件与检查方案的映射；
- 自动触发或批量生产检查；
- 检查流程分支或依赖图；
- 配置热重载；
- 数据库及检查结果持久化；
- 历史检查记录；
- 摄像头故障恢复；
- 无法协作取消的任务恢复；
- 旧版配置或数据兼容；
- 执行外部副作用的检查算子；
- 文本表达式 DSL、脚本、函数调用、用户自定义操作符和变量赋值；
- Expression 中的算术、聚合、集合、空值、正则表达式、字符串转换和隐式类型转换；
- Expression 对嵌套对象路径、未声明 StageOutput 字段、Frame、InspectionMetadata 或派生产物的直接读取；
- Expression 的浮点容差比较和 Bool、String 顺序比较。
